Critical

CRITICALUnescaped toast message renders arbitrary HTML (stored XSS vector)

Line 824 — toast() function · el.innerHTML = `…${msg}…`

The msg argument is injected into innerHTML without escaping. Several callers pass data derived from stored user input — most notably a.firstName, a.game.title, v.name (saved view name) — directly into toast(). Because a.firstName is stored verbatim from the registration form input after esc() is stripped on parse, a registrant who enters a name like <img src=x onerror=alert(1)> will have that payload executed every time an organizer performs an action on that player (check-in, approve game, promote, etc.).

// line 824
el.innerHTML=`${icon(ic||ics[t])}<span class="tmsg">${msg}</span>…`;

// example callers that pass unescaped user data:
toast(`${esc(a.firstName)} checked in ✓`, …)         // ✓ escaped
toast(`"${esc(a.game.title)}" approved…`, …)          // ✓ escaped
toast(`View "${esc(v.name)}" applied`, …)              // ✓ escaped
// BUT:
el.innerHTML injects the already-constructed string — if any caller
forgets esc(), or if msg itself comes from a string that embeds HTML tags
(e.g. via the confirm dialog body), those tags execute.
Fix: Change toast() to use textContent for the message span, or run esc(msg) before interpolation. Use el.querySelector('.tmsg').textContent = msg after creating the element via createElement.

High

HIGHCryptographically weak session tokens — trivially guessable

Lines 592–593 — uid() and mkToken()

Math.random() is not cryptographically secure. The 6-character base-36 token (VA-XXXXXX) produced by mkToken() is used as the sole authentication credential for the entire Prep Hub. It has only ~2.18 billion possible values, and Math.random() is seeded from a 64-bit state — in V8 it can be predicted after observing a handful of outputs. An attacker with read access to any token can enumerate and forge others.

const uid    = () => Math.random().toString(36).slice(2,10);  // ~2^41
const mkToken = () => "VA-" + Math.random().toString(36).slice(2,8).toUpperCase(); // ~2^31
Fix: Replace with crypto.getRandomValues(). For tokens: "VA-" + [...crypto.getRandomValues(new Uint8Array(6))].map(b => b.toString(36).padStart(2,'0')).join('').slice(0,8).toUpperCase(). For IDs: crypto.randomUUID() (widely supported).
HIGHUnvalidated user-supplied game link rendered in an href attribute — javascript: URL injection

Lines 1494, 1795 — showcase and cabinet modal

Game submission allows a player to enter a free-form URL that is stored verbatim and later placed directly into an href attribute after only HTML-escaping via esc(). HTML-escaping does not prevent javascript: URLs. A malicious player can submit javascript:alert(document.cookie) as their game link; it will appear as a clickable "SOURCE" / "OPEN SOURCE LINK" button for all users, including organizers.

// line 1494
<a href="${esc(g.link)}" target="_blank" rel="noopener noreferrer">SOURCE</a>
// esc() encodes < > & " ' — but NOT javascript: protocol
Fix: The existing urlOk() validator (line 914) already enforces http: or https: — apply it on render too, not just on submit. Guard each usage: href="${urlOk(g.link) ? esc(g.link) : '#'}". Also strip javascript:/data: from stored links at submission time.
HIGHUnvalidated data-part attribute used as direct object key — prototype pollution / state corruption

Line 1986 — change event handler

t.dataset.part (from an HTML attribute emitted during render) is used without validation as a key into a.checklist[t.dataset.part]. While the attribute is generated by trusted code today, any DOM manipulation or DevTools injection can create a checkbox with data-part="__proto__" or data-part="constructor" and trigger prototype pollution. At minimum, it allows injecting arbitrary keys into the attendee's checklist object, corrupting state serialized to localStorage.

// line 1986
a.checklist[t.dataset.part][+t.dataset.idx] = t.checked;
// no whitelist check on t.dataset.part
Fix: Validate against the allow-list: const VALID_PARTS = new Set(PARTS.map(p => p.key)); if (!VALID_PARTS.has(t.dataset.part)) return; Similarly validate t.dataset.idx against PARTS.find(p=>p.key===t.dataset.part)?.n.

Medium

MEDIUMTemplate literal inside head() uses wrong quote — message composer shows literal ${recips.length}

Line 1817 — composerHTML()

The head() call in composerHTML uses a regular string with a template expression that is never interpolated because the outer string uses single quotes, not backticks. The modal title will always display the literal text MESSAGE COMPOSER · ${recips.length} RECIPIENT instead of the actual count.

// line 1817 — BUG: single-quoted string, not a template literal
head("MESSAGE COMPOSER · ${recips.length} RECIPIENT" + (recips.length===1?"":"S"))
//    ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ never interpolated
Fix: Change the outer quotes to backticks: head(`MESSAGE COMPOSER · ${recips.length} RECIPIENT${recips.length===1?"":"S"}`)
MEDIUMInfinite loop risk — promoteWaitlist() can loop if registered() never shrinks

Lines 865–874 — promoteWaitlist()

The while(seatsLeft()>0 && waitlisted().length) loop recalculates seatsLeft() each iteration by counting registered(). If a promoted attendee's status is set to "registered" but registered() still returns the same set (e.g. a subtle ordering bug), the loop will never terminate and will freeze the browser. It is not strictly infinite today, but the lack of a guard makes this fragile.

Fix: Add a safety counter: let guard = waitlisted().length; while (guard-- > 0 && seatsLeft() > 0 && waitlisted().length).
MEDIUMNo validation of parsed localStorage state — malformed data crashes the app silently

Line 729 — boot-time state load

The app parses raw localStorage JSON and only checks state.v !== 1. It performs no structural validation. If localStorage is corrupted or tampered with (missing attendees array, non-array outbox, etc.), downstream code (e.g. registered(), array spreads) will throw unhandled exceptions, leaving the app in a broken state with no user-visible error.

Fix: After parsing, assert the minimum shape: if (!Array.isArray(state?.attendees) || !state.settings) state = seed();

Lines 1411–1417 — gameBlock() form

The .err paragraph for e.link is rendered twice — once after the link <input> (line 1411–1413) and again after the file upload section (line 1416–1417). When the link validation error fires, two identical error messages appear stacked under the form.

// line 1411
<p class="err">${e.link ? … : ""}</p>
// …file upload block…
<p class="err">${e.link ? … : ""}</p>  // ← duplicate
Fix: Remove the second duplicate error paragraph (line 1417) or introduce a separate e.file key for the file upload error.
MEDIUMPhone auto-formatter does not restore caret position — cursor jumps to end on edit

Lines 2007–2009 — input event handler

When the phone field is edited mid-string, the value is reformatted but selectionStart (captured before formatting) is never restored after t.value = fmtPhone(t.value). The cursor always jumps to the end of the input, making it impossible to correct digits in the middle of a phone number.

if(k==="phone"){
  const pos = t.selectionStart;
  t.value = fmtPhone(t.value);
  // pos is captured but never used — cursor jumps to end
}
Fix: After reformatting, restore the caret: t.setSelectionRange(pos, pos); (or calculate an adjusted offset accounting for added formatting characters).

Low

LOWdir-search input bypasses the focus-restoration system — reinventing the wheel unsafely

Line 2005 — input event handler

The directory search handler directly sets $("#app").innerHTML = viewDirectory() and manually restores focus, bypassing the centralized renderApp() flow (which also restores focus via the data-fk system). If viewDirectory() throws, #app is left blank with no recovery path.

Fix: Set ui.dirQ = t.value and call renderApp() (the data-fk="dirq" attribute on the input already makes focus restoration automatic).
LOWMissing sandbox attribute on the game preview <iframe>

Line 1792 — modalHTML() cabinet modal

The <iframe> that plays user-submitted games has no sandbox attribute. While it currently only loads srcdoc content (the built-in breakout game), if a future feature changes this to load a submitted URL, the frame will have full origin privileges. Adding sandbox now is defence-in-depth.

Fix: Add sandbox="allow-scripts allow-pointer-lock" to the iframe element. This is sufficient for a canvas game and blocks top-level navigation, form submission, and popups.
LOWdocument.execCommand("copy") fallback is deprecated

Line 906 — copyText() fallback

document.execCommand("copy") is deprecated in all major browsers and may be removed in future versions. The primary path uses navigator.clipboard.writeText() correctly, so the fallback is only reached in contexts where the Clipboard API is unavailable (old browsers, insecure contexts). It should still be replaced.

Fix: Replace the fallback with a user-visible prompt (window.prompt("Copy this link:", t)) which works in all contexts without relying on deprecated APIs.
LOWSound toggle toast message is inverted — says "Sound muted" when muting, but reports old state

Line 1914 — sound action handler

The mute toggle flips state.settings.muted before the toast is built. The toast message then reads state.settings.muted ? "Sound muted" : "Sound on". This is correct. However, the conditional plays SFX.coin() after setting muted = true can never fire (since it checks !state.settings.muted which would be false). The coin sound when un-muting will never play because the state check inside SFX (line 788) gates on state.settings.muted which was set to false first — this part actually works, but the logic is confusing and fragile.

Fix: Capture the new value before toggling: const nowMuted = !state.settings.muted; state.settings.muted = nowMuted; then use nowMuted consistently in the toast and SFX call. Add a comment explaining the sequencing.

Informational

INFOAll attendee data stored in localStorage with no expiry or size cap

Lines 729–731 — state persistence

localStorage is capped at 5–10 MB per origin. The outbox is trimmed at 250 messages (line 835), but the attendee array is unbounded. In a real deployment, 1 000+ attendees with game objects could approach the storage limit. When setItem throws a QuotaExceededError, the silent catch on line 730 swallows it and state is not persisted — data appears saved but is lost on reload.

Note: The app is explicitly labelled a demo; this is expected. For production, replace localStorage with a server-side backend as already noted in the UI.
INFONo Content Security Policy header or meta tag

Lines 3–12 — <head> section

There is no Content-Security-Policy meta tag. Because the page generates HTML via template literals and sets innerHTML, a CSP would be difficult to apply to this architecture — but its absence means any XSS payload (see Critical finding) executes without restriction. The unsafe-inline requirement from the inline <script> and <style> blocks further limits what a CSP could achieve without a refactor.

Note: For a production build, extract scripts and styles to separate files and apply a strict CSP.
INFOOrganizer dashboard has no authentication — accessible to any user

Line 1554 — viewOrganizer()

The organizer dashboard is reachable by anyone who navigates to #/organizer. It allows approving/rejecting games, editing attendee records, checking in players, resetting all data, and exporting the full roster. There is no password, session check, or role gate. The UI says "STAFF ONLY · NAMED ACCESS" but this is cosmetic only.

Note: Expected for a demo. In production, protect this route with server-side session authentication; never expose PII export endpoints client-side.
